# Frontier64 Stage Brief(F64 단계 개요)

- stage(단계): `stage_frontier_64__independent_pf_source_after_inverse_signal_memory`
- run(실행): `frontier64A_stage_open_independent_pf_source_after_inverse_signal_memory_v1`
- work_family(작업군): `experiment_design(실험 설계)`
- primary_skill(주 스킬): `obsidian-experiment-design(실험 설계)`
- status(상태): `open_stage_hypothesis_design_no_authority(단계 개방 설계, 권위 없음)`

## Hypothesis(가설)

Cluster-level loss propagation source(구간/군집 단위 손실 확산 원천)가 진입 전에 loss-cluster hazard(손실 군집 위험)를 걸러내면, F61~F63 side allocation(방향 배분) 계열과 다른 independent PF source(독립 수익 팩터 원천)를 만들 수 있는지 시험한다.

## Novelty Delta(신규성 차이)

- prediction unit(예측 단위): individual trade success(개별 거래 성공)가 아니라 local loss-cluster hazard(국소 손실 군집 위험)를 본다.
- model role(모델 역할): side-allocation model(방향 배분 모델)이 아니라 admission hazard gate(진입 위험 게이트)다.
- entry surface(진입 표면): simple symmetric entry surface(단순 대칭 진입 표면)를 먼저 잠그고, F64는 hazard timing(위험 시점)만 검증한다.
- failure label(실패 라벨): 실패하면 `negative_memory_loss_cluster_hazard_failed_independent_pf_source(부정 기억, 손실 군집 위험 독립 PF 원천 실패)`로 닫는다.

## Do Not Repeat(반복 금지)

- F55 sparse admission(희소 진입 허용)을 새 이름으로 반복하지 않는다.
- F56 adverse excursion(불리 이동), F57 fast exit(빠른 청산), F58 friction survivability(마찰 생존성) 라벨을 재포장하지 않는다.
- F61/F62/F63 side allocation(방향 배분), event compression(이벤트 압축), inversion(역전)을 수리하지 않는다.
- first MT5 runtime probe(첫 MT5 런타임 탐침) 실패 뒤 threshold repair(임계값 수리)를 하지 않는다.

## Required Evidence(필수 근거)

- proxy(프록시): F63 대비 PF(수익 팩터), DD(손실폭), density(거래 빈도), smoothness(매끄러움)를 함께 비교한다.
- pre-expensive Grok review(비싼 검증 전 그록 검토): MT5/WFO(MT5/워크포워드) 전에 실행한다.
- MT5 runtime probe(MT5 런타임 탐침): stage closeout(단계 마감) 전에 실행하고 proxy-runtime gap(프록시-런타임 차이)을 기록한다.
- closeout(마감): completion candidate(완성 후보), preserved clue(보존 단서), negative memory(부정 기억), invalid setup(무효 설정), blocked(차단) 중 하나로 닫는다.

## Claim Boundary(주장 경계)

Allowed vocabulary(허용 표현): scout clue(탐색 단서), seed surface(씨앗 표면), runtime probe observation(런타임 탐침 관찰).

Forbidden claims(금지 주장): completion(완성), baseline(기준선), promotion(승격), runtime authority(런타임 권위), live readiness(실거래 준비), Goal Achieve(목표 달성).
