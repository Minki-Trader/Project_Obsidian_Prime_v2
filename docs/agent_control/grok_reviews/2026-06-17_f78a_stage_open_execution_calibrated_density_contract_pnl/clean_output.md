## Grok Review — F78 Stage-Open Direction

**Advice classification:** `accepted_with_conditions` (조건부 수용)

**Claim boundary:** This is a stage-open scope critique only. No completion, baseline, promotion, runtime authority, live readiness, or Goal Achieve.

---

### Sufficiency vs F77 / F71–F77 repeat loops

**Yes, directionally different enough** — if F78 is executed as an economic-contract rebuild, not as F77 with new labels.

From the bounded snapshot, F77 failed on two concrete, repeatable faults:

1. **Proxy money not broker-contract calibrated**
2. **Density denominator used active dates, not calendar days**

F78’s axis contract targets both directly:

| F77 negative memory | F78 counter-move |
|---|---|
| Uncalibrated proxy money | `label_target`: broker contract P/L utility, fill eligibility |
| Active-date density | `label_target`: calendar density |
| Weak meaningful signal / no final-like reference | `feature_set` + `model_family` separate source alpha from parity repair |
| Runtime economics explained after failure | `risk_logic`: DD / loss-streak control before MT5 materialization |
| Signal count vs trade count confusion | `trade_shape`: co-designed entry/exit/hold/cooldown/occupancy |

That is **more than a parity-loop rerun**. The preserved clues (point-unit repair, ONNX/EA parity path, runtime bridge) are appropriate as **plumbing**, not as the hypothesis — consistent with “reference, not inheritance.”

**Repeat-loop risk remains** if execution drifts back to:

- Parity repair as the main lever
- Broad sweeps across six axes without a narrow proxy gate
- `regime_session_split` slices so small they recreate tiny-slice overfit (the contract already names this risk)

F77F OOS (net 4.48 / PF 1.23 / DD 1.41 / tpd 0.1487) is weak but not zero. F78 should **test whether economics fix the proxy→runtime gap**, not assume F77 runtime is already “close.”

---

### Scoping for proxy scout → mandatory MT5 Runtime Probe

**Partially scoped; needs tightening before runs.**

What is well scoped in the snapshot:

- Export-aware model gating (`small MLP proxy-only until export checked`)
- Pre-MT5 risk embedding
- Explicit broad-sweep lists per axis (exploration allowed, not hidden)

What is **not** yet scoped enough for `proxy scout → mandatory MT5 Runtime Probe`:

1. **No proxy gate criteria** — which KPIs (contract-calibrated net, calendar-density utility, PF floor, DD penalty) must pass before MT5 probe?
2. **No probe budget** — six axes × many sweep values can explode combinatorially; without a cap, proxy scout becomes an endless F71–F77 loop with richer vocabulary.
3. **No Tier A / Tier B / combined record requirement** in the F78 open packet (project rule for alpha exploration after Stage 10).
4. **No stop condition** — when is “contract P/L utility rebuild” negative vs inconclusive vs worth one MT5 probe?

So: **direction fits proxy→probe in intent**, but **operating contract for probe selection is incomplete** in this snapshot.

---

### Conditions for Codex (local verification owned by Codex, not Grok)

1. **Bind preserved clues to infrastructure only** — point-unit repair, ONNX/EA parity, runtime bridge must not become the primary success narrative.
2. **Define a narrow proxy gate before any MT5 probe**, e.g.:
   - broker-contract-calibrated utility beats a trivial baseline on **calendar** density
   - density denominator explicitly calendar days (not active dates)
   - at least one non-parity feature family beats parity-only repair on the same label
3. **Cap sweep cardinality** — staged passes (label/risk first, then trade_shape, then regime) rather than full Cartesian product across six axes.
4. **Mandatory MT5 Runtime Probe only for proxy survivors** — top-N by contract utility + calendar density, with export path checked for chosen model family.
5. **Record Tier A separate, Tier B separate, Tier A+B combined** (or mark `missing_required` with reason).
6. **Pre-register negative memory triggers** — e.g. meaningful-signal count 0 again, or proxy improves while MT5 PF/tpd stay flat → label/density fix insufficient.

---

### Final Codex direction (Grok recommendation)

**Proceed with F78 open as `execution_calibrated_density_contract_pnl_rebuild`**, but treat it as a **contract-economics rebuild stage**, not F77 continuation.

Open is **justified** because F78 directly answers F77’s documented proxy failures and widens the hypothesis beyond parity-only repair.

**Do not start broad runs** until proxy gate, probe budget, and Tier pairing are written into the stage-open packet.
