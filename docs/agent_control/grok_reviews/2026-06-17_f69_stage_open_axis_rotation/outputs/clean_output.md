## F69 Stage Open Review (F69 단계 개방 검토)

**Review size:** medium review (중간 검토) — bounded snapshot (제한 스냅샷) + one focused question (집중 질문 하나)  
**Claim boundary:** `stage_open_design_only` — no completion/baseline/promotion/runtime authority/live readiness/Goal Achieve

---

### 1. accepted (수용)

**Axis rotation is the right pivot (축 회전이 맞는 전환).**  
F68 negative memory (부정 기억) says risk-only repair (위험 단독 수리) and SL/TP/ATR width tuning (손절/익절/평균진폭 폭 조정) did not create a PF source (수익 팩터 원천). Moving from lifecycle-cost aggregate labels (생명주기 비용 집계 라벨) to first-hit opportunity labels (선도달 기회 라벨), and from dense every-bar scoring (매 봉 촘촘한 점수화) to sparse event admission (희소 이벤트 진입 허용), is a coherent response — not a cosmetic rename.

**Preserved clues are used, not discarded (보존 단서를 버리지 않고 씀).**  
Keeping F68F signal/feature parity (신호/피처 동등성) as a materialization bar (구현 기준), and F68J unit-corrected ATR telemetry (단위 보정 평균진폭 기록) as a variant-differentiation lesson (변형 구분 교훈), respects F68 without inheriting authority (권위 상속 없음).

**F69A design-only gating is sound (F69A 설계 전용 게이트가 타당).**  
Opening with `frontier69A_stage_open_axis_rotation_hypothesis_design_v1` before F69B broad proxy sweep (넓은 프록시 탐색) matches the claim boundary and avoids repeating F68’s pattern of running variants before the hypothesis surface is defined.

**Interpretable compact model families fit the stage (해석 가능한 압축 모델 계열이 단계에 맞음).**  
Linear/shallow tree/optional EBM-like scouts (선형/얕은 트리/EBM 유사 탐색) support “where does PF come from?” (PF가 어디서 오는가?) before another ONNX-heavy path that could hide axis confusion.

**Explicit regime/session splits are necessary (명시적 장세/세션 분할이 필요).**  
An event-first regime/session/candle-path model (이벤트 우선 장세/세션/캔들 경로 모델) without bucketed comparison (구간별 비교) would be hard to falsify. Session age, open/mid/late, trend/chop/vol pockets (세션 경과, 초중후반, 추세/횡보/변동성 포켓) give F69B something measurable.

**Risk stays secondary — correctly stated (위험 보조 원칙이 맞게 적혀 있음).**  
The proposal explicitly forbids SL/TP width repair as the main PF source. That directly targets F68’s core negative memory.

### 2. rejected (거절)

**Do not treat F68J OOS metrics as F69 success preconditions (F68J 표본외 지표를 F69 성공 전제로 쓰지 말 것).**  
F68J OOS DD 13.76% and density 6.69/day (일 6.69회) are preserved clues (보존 단서), not a baseline or target to “beat.” Using them as implicit F69 KPIs would overclaim and pull F69 back toward risk/density repair on the old surface.

**“Changing multiple major axes at once” is direction, not proof (여러 축 동시 변경은 방향이지 증명이 아님).**  
F68 already showed that changing risk alone failed the four-axis target (네 축 목표). F69 must not claim that feature + label + trade-shape rotation automatically fixes economics — only that it changes the search space. Any wording that sounds like “this will create PF” should stay at hypothesis level.

**“Do not reuse F68F feature/model surface as-is” needs a hard boundary, not a soft preference (F68F 피처/모델 표면 그대로 재사용 금지는 선호가 아니라 경계여야 함).**  
Without a written exclusion list in F69A, F69B can silently drift into F68F ONNX reuse with thin event wrappers — which would repeat F68 under a new stage name.

**Pre-MT5 Grok review + mandatory MT5 Runtime Probe should not be framed as due at stage open (사전 MT5 그록 검토 + 필수 MT5 탐침을 단계 개방 시점 의무로 말하지 말 것).**  
Those gates belong after F69B shows meaningful proxy signal (의미 있는 프록시 신호). Stating them in the open packet is fine as future gates; treating them as imminent invites premature runtime narrative.

**Optional EBM-like scout is a scope trap if unbounded (EBM 유사 탐색은 범위 통제 없으면 함정).**  
At design-only open, EBM should stay explicitly optional and subordinate to linear/shallow-tree falsification — not a parallel heavy track that delays axis clarity.

### 4. drift_risks (드리프트 위험)

**Risk-only repair loop via “first-hit SL/TP” (선도달 손절/익절로 위험 단독 수리 반복).**  
First-hit labels and fixed max hold (고정 최대 보유) can devolve into another SL/TP width sweep if feature/model work stalls. Symptom: high F69B run count on cooldown/hold/SL/TP grids with thin event-feature movement.

**Signature collapse under “compact” features (압축 피처 명목하에 서명 붕괴).**  
F68 capped ATR caused signature collapse (서명 붕괴). A “compact event surface” built mostly from volatility/session proxies could collapse variants the same way unless telemetry and hash differentiation are first-class in F69A.

**F68F parity success becomes the wrong optimization target (F68F 동등성 성공이 잘못된 최적화 목표가 됨).**  
Chasing signal=0, feature=0 parity (동등성) before proxy economics show a new PF source can recreate F68’s near-four-axis repair trap: pretty parity, weak validation PF.

**Dense scoring in disguise (촘촘한 점수화의 변장).**  
Event admission + cooldown can still become every-bar scoring with a threshold mask if the event definition is too loose. That repeats F68’s dense lifecycle proxy path with new vocabulary.

**Multi-axis change without attribution (다축 변경인데 기여 분해 없음).**  
Rotating feature, label, model, and trade shape together makes it impossible to know what failed. F69B broad sweep without per-axis ablation (축별 소거) will look productive while repeating F68’s “couldn’t hit four axes at once” outcome.

**ONNX scout creep (온엑스 탐색 확장).**  
Despite interpretable-first intent, pressure to “just materialize like F68F” can push F69 toward ONNX before proxy meaning is shown — re-entering runtime economics gap work without a new PF hypothesis.

### 5. final_direction_advice (최종 방향 조언)

**Open F69 — but lock F69A as an axis-rotation contract, not a theme rename.**

Recommended sequence:

1. **F69A must publish an axis diff table:** F68 vs F69 rows for feature surface, label family, model family, trade shape, regime split, and risk role — plus an explicit F68F reuse prohibition list.
2. **F69B proxy sweep should be staged, not one broad blob:**  
   - Phase 1: event definition + first-hit labels only, linear/shallow baseline, risk frozen to a single conservative template.  
   - Phase 2: regime/session buckets.  
   - Phase 3: trade-shape knobs (cooldown, max hold) only if Phase 1 shows proxy PF movement not explainable by density/DD repair alone.
3. **Falsification criteria before any MT5 talk:** e.g. proxy must show separation across session/regime buckets and beat a label-shuffled control — not just beat F68J OOS DD/density anecdotes.
4. **Keep F68J metrics as clues only** in closeout language; do not encode them as F69 promotion thresholds.

**Verdict:** The proposed F69 direction is **directionally sound** and appropriately bounded at stage open. The main failure mode is not wrong hypothesis — it is **insufficient decomposition**, allowing F69B to become F68-style risk/density repair with event vocabulary. Tighten F69A into an enforceable axis contract; stage F69B sweeps with per-axis ablation; defer MT5 until proxy signal is locally demonstrated under that contract.
