## Accepted(수용)

**1. Probe timing and scope(탐침 시점·범위)**
F73 lifecycle(단계 생명주기) requires one MT5 runtime probe(런타임 탐침). F73C produced a dual-positive near-miss(검증+표본외 양수 근접 단서) — weak for promotion(승격), sufficient for observation(관찰). A single narrow probe(단일 좁은 탐침) matches stage discipline(단계 규율); another proxy sweep(프록시 추가 탐색) before MT5 would repeat F73B/C pattern(0 scout clue, 0 meaningful) without new runtime evidence(런타임 근거).

**2. Claim boundary(주장 경계)**
“Seed surface(씨앗 표면), not success(성공 아님)” and “bridge materialization(연결 물질화), not direct F73C authority(직접 F73C 권위 아님)” are correct. PF ~1.3 and tpd ~1.25 are probe observations(탐침 관찰) only — not baseline(기준선), promotion(승격), or runtime authority(런타임 권위). That boundary is preserved if Codex keeps it in receipts(영수증) and closeout(마감).

**3. Surface selection(표면 선택)**
`fwd12` + `session_regime_core` + `cash_open` + long-only(롱만) + `target_tpd ~1.25` stays aligned with F73C best `f73c_0002`, not a new trade-shape invention(새 거래 형태 발명). Skipping fwd18 inverse high-DD candidates(18봉 역방향 고손실폭 후보 제외) avoids economics-by-DD tradeoff(손실폭으로 경제성 희생) that would muddy gap attribution(간극 원인 규명).

**4. Documented ONNX repair(기록된 ONNX 수리)**
`small_nn_16` first, then `extra_trees_ref` only if export/parity fails — not silent family swap(조용한 모델 계열 교체). That supports parity audit(동등성 감사) and repair traceability(수리 추적).

**5. Anti–F72 trade-shape-first(거래 형태 우선 수리 회피)**
Plan does not force 5–10 tpd(일 5–10회) or reshape entries before runtime read(런타임 판독 전 진입 형태 변경). It tests whether session/regime rotation(세션/장세 회전) survives handoff(인계) at proxy-calibrated density(프록시 보정 밀도). That is economics-gap observation(경제성 간극 관찰), not trade-count repair(거래 수 수리) first.

## Rejected(거절)

**1. “Dual-positive near-miss” as probe justification strength(근접 단서를 탐침 정당화 근거로 과대)**
48 dual-positive with **scout clue 0, meaningful 0** means F73C is still proxy-inconclusive(프록시 불충분). MT5 probe is **lifecycle obligation(생명주기 의무)** and **handoff test(인계 시험)** — not evidence that F73C is a viable completion path(완성 경로).

**2. Implicit equivalence: binary proxy ↔ 3-class bridge(이진 프록시와 3분류 연결의 암묵적 동일시)**
Even with local parity on the bridge(연결 모델 로컬 동등성), you must **not** report “F73C reproduced in MT5.” Receipts must say **bridge-derived runtime probe(연결 기반 런타임 탐침)**. Parity passes on the bridge do not retroactively validate the original binary proxy(원래 이진 프록시 소급 검증 아님).

**3. Success language creep(성공 표현 확장)**
Weak proxy PF (~1.31–1.36) will likely compress further under spread/slippage/latency(스프레드·슬리피지·지연). If runtime KPI is weak, **record proxy/runtime gap(프록시/런타임 간극)** — do not reframe as “partial success(부분 성공)” or “promotion candidate(승격 후보).”

**F72 trade-shape-first repeat(거래 형태 우선 수리 반복):** **Avoided** by holding proxy tpd/PF as observation bars(관찰 기준) and not chasing 5–10 tpd in this probe. **Risk remains** if post-probe repair defaults to entry-count or veto-tape tweaks before attributing economics gap(경제성 간극 귀인 전 진입 수·테이프 조정).
