### Main benefits

| Benefit | Effect |
|--------|--------|
| **Breaks numeric lineage** | `Stage365` signals “continue 364.” `frontier_01` signals “new bounded campaign.” |
| **Forces decision weight over run count** | 226 runs in 364 did not yield strict joint pass; a frontier must be judged by thesis outcome, not activity. |

| **Improves comparability** | Uneven stages (design-only vs 471-run campaigns) become comparable if each frontier has the same opening/closing contract. |

### Main failure modes

1. **Cosmetic rename** — `frontier_02` is really `stage365` if naming changes but behavior does not (implicit continuation, “after_stage364” lineage).
2. **Archive amnesia** — “independent” becomes “ignore prior work”; reusable artifacts (parity contracts, feature modules, failure boundaries) get rediscovered expensively.
3. **Frontier sprawl** — many 1–2 run micro-frontiers recreate today’s 277 single-run stage problem under a new label.
4. **Repair laundering** — repair lanes relabeled as frontiers without a novelty delta; repair loops continue with fresh IDs.
5. **Undefined decision weight** — without a rubric, “decision weight” becomes subjective or gamed (e.g. long prose charters, short useless runs).
6. **Weak prior-stage scan** — scan becomes ritual (“consulted archive”) without citing specific register rows or do-not-repeat entries.
7. **Artifact/path drift** — new `frontiers/` layout without lineage rules loses traceability to Stage12–364 registers.
8. **Tier discipline slip** — frontiers skip Tier B or combined reads and repeat Tier-A-only overclaim patterns.

### Minimum guardrails before adoption

**A. Frontier charter (required at open)**
Each frontier must ship, before any run:

- `frontier_thesis` — one testable question
- `novelty_delta` — what is genuinely new vs archive
- `prior_stage_scan` — cited register rows / clue IDs, not vague “reviewed 364”
- `do_not_repeat_list` — explicit prohibitions (e.g. lower-floor rank micro-tuning loops)
- `exit_rule` — stop on negative memory, clue preservation, or bounded pass/fail
- `claim_boundary` — no operating promotion, runtime authority, baseline, Goal Achieve

**B. Reference-not-inheritance (hard forbid)**
Frontiers may **read**:

- `negative_result_register`, `idea_registry`, failure memory, preserved clues, reusable `foundation/` modules

Frontiers may **not import**:

- selected baseline, promotion history, runtime authority, “winner” packages, implicit “continue last run” defaults

**C. Lane separation**
Two lanes with different open contracts:

- `exploration_frontier` — hypothesis-driven, minimum depth before close
- `repair_frontier` — only when repairing a named artifact with bounded scope; cannot open without citing broken artifact + repair boundary

Effect: repair stops masquerading as fresh exploration.

**D. Decision-weight rubric (replace run count as success proxy)**
Score frontiers on a small fixed set, e.g.:

- thesis resolved (yes/no/blocked)
- novelty actually tested (not just renamed)
- negative memory added (count + specificity)
- preserved clues with explicit use limits
- external verification attempted where claim needs it
- repair-to-exploration ratio inside the frontier

**E. Minimum depth + hard stop**
Avoid 1-run frontier churn:

- minimum scout + confirmation pattern (or explicit `blocked` with reason)
- hard stop when exit_rule fires — no “one more letter run” without new charter amendment

**F. Archive interface, not archive inheritance**
Prior stages are queried through **indexes** (registers, ledgers, failure maps), not by copying prior stage folder structure or `next_stage` chains.

**G. State identity**
`workspace_state` should track `active_frontier_id`, not auto-increment `current_stage_id` for new work. Stage12–364 remain frozen archive.

**H. Closeout vocabulary enforcement**
Reuse exploration mandate allowed words only. Any forbidden closeout word triggers `needs_explicit_promotion_packet`.

**I. Tier pairing unchanged**
Stage10+ tier rules still apply inside frontiers: Tier A separate, Tier B separate, Tier A+B combined — or `missing_required` / `blocked` honestly recorded.
